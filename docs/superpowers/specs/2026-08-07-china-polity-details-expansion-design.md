# 中国非主线政权详情补全设计

## 1. 背景与目标

Crownline 当前收录 73 个中国历史实体，其中包括 71 个政权和 2 个历史分期。16 个中国主线政权已经具备人物与统治任期数据，其余 55 个非主线政权大多只有简短说明，尚无统治者详情。结构化历史关系与事件也尚未录入。

本次工作以现有 55 个非主线中国政权为完整目标，补充：

- 约 100 至 200 字的政权简介；
- 正式在位君主的完整序列；
- 对政权实际统治具有重要影响的摄政者、共治者和主要争位者；
- 人物、任期、年代争议与置信度信息；
- 支持政权沿革和统治任期的可追溯来源。

工作按历史时期分批连续完成。每批完成来源核对、数据录入、校验、测试和人工抽查后直接进入下一批，直到 55 个目标政权全部达到验收标准。

## 2. 范围与非目标

### 2.1 本次范围

- 新、曹魏、蜀汉、孙吴；
- 两晋与十六国阶段的 16 个并立政权；
- 南北朝阶段的 9 个并立政权；
- 武周、五代十国及吐蕃、渤海、南诏等 19 个同期政权；
- 辽、大理、西夏、金、大蒙古国、后金、南明，共 7 个政权。

以上合计 55 个政权。

### 2.2 非目标

- 不新增当前时间轴尚未收录的地方割据、叛乱政权或短暂称帝者；
- 不扩展都城、疆域、制度、经济、军事等独立结构化字段；
- 不录入结构化历史关系或事件；
- 不重新设计详情弹窗和时间轴页面；
- 不引入数据库、CMS、服务端接口或新的运行时依赖；
- 不修改既有 16 个主线政权的史料口径，除非新数据触发现有校验错误或发现明确的关联问题。

## 3. 方案选择

采用“按历史时期纵向切分、每批形成完整闭环”的方案。每批同时完成来源、简介、人物、任期、争议标注、测试和人工抽查。

未采用先统一补简介、再统一补任期的两遍方案，因为前半程会长期留下不完整详情，后续任期资料还可能反向影响简介。未采用全部录入后统一验证，因为跨记录错误、年代越界和来源缺失会积累到最后，显著增加定位与返工成本。

## 4. 数据边界

本次沿用现有 schema v3，不扩展 JSON Schema、TypeScript 领域类型和运行时详情包结构。

每个政权继续维护在 `src/data/source/entities/china/<entity-id>.json` 中：

- `description`：扩写为约 100 至 200 字，覆盖建立背景、统治核心或主要疆域、关键演变和终结方式；
- `persons`：记录人物主名称、常用姓名、庙号、谥号或其他常见别名；
- `reigns`：记录正式君主及重要摄政、共治和争位任期；
- `reignVacancies`：只记录有明确史料支持的空位，不从普通资料缺口推导空位；
- `chronologyNote`、`confidence` 与 `confidenceNote`：表达所采用的年代口径、争议和不确定性；
- `sourceRefs`：引用集中维护在 `src/data/source/sources/` 中的来源记录。

现有生成器继续负责聚合分片、执行全量校验，并为每个实体生成包含人物、任期、空位和来源闭包的详情包。首屏索引、详情懒加载和页面组件不需要因本次数据补全而修改。

## 5. 史料与统治者口径

### 5.1 来源标准

优先使用中国政府、博物馆、高校、学术机构和权威工具书的公开页面；必要时使用可靠历史年表补足统治者序列。每个政权至少需要一项直接支持其沿革和年代的来源，统治者任期也必须绑定来源。

同一权威年表可以被同一时期的多条人物与任期记录复用，但每条业务记录仍需保留明确的 `sourceRefs`。来源之间有细微年代差异时，采用主流口径并记录替代说法；无法可靠确认的年份不得伪装成精确年份。

### 5.2 人物范围

收录正式在位君主，并补充对政权实际统治具有重要影响的摄政者、共治者和主要争位者。短暂叛乱者、未实际控制该政权的自称者，不混入正式君主序列。

同一历史人物只创建一条人物记录。庙号、谥号、姓名和常见异名通过名称与别名表达，避免因为称谓不同重复建档。

### 5.3 任期与争议

- 任期两端使用现有闭区间语义；
- 任期必须完整落在所属政权的某个存在区间内；
- 政权中断、复立或改朝换号继续使用多个存在区间表达；
- 争位者、摄政者和共治者使用现有角色字段，不只在简介中描述；
- 年份不确定时使用 `circa` 或 `unknown` 精度，并提供必要说明；
- 身份或年代存在实质争议时降低置信度并写明采用口径；
- 资料未整理的年份保持“资料尚未校订”语义，不能自动判定为无人统治或明确空位。

## 6. 分批执行

### 批次一：汉与三国

补全新、曹魏、蜀汉和孙吴，共 4 个政权。该批作为首个完整闭环，用于验证简介深度、人物别名、禅让或取代边界，以及多政权并立时的任期表达。

### 批次二：两晋与十六国

补全前凉、成汉、汉赵、后赵、前燕、前秦、后秦、后燕、西秦、后凉、南凉、北凉、南燕、西凉、胡夏和北燕，共 16 个政权。重点处理国号重名、族属与称谓差异、复国中断、争位和年代分歧。

### 批次三：南北朝

补全北魏、东魏、西魏、北齐、北周、刘宋、南齐、梁和陈，共 9 个政权。重点处理分裂继承、禅代边界、傀儡君主与权臣摄政。

### 批次四：隋唐与五代十国及同期区域政权

补全武周、后梁、后唐、后晋、后汉、后周、吴、南唐、吴越、闽、楚、前蜀、后蜀、南汉、荆南、北汉、吐蕃、渤海和南诏，共 19 个政权。重点处理短任期、国号重名、地区称谓、世系口径和同时期多政权来源复用。

### 批次五：辽夏金元与明清并立政权

补全辽、大理、西夏、金、大蒙古国、后金和南明，共 7 个政权。重点处理多语言姓名与称号、帝号变更、政权转型边界、并立君主和南明争位。

## 7. 单批数据流

每一批按照以下顺序执行：

1. 核对目标政权的现有名称、存在区间和年代说明；
2. 检索并筛选符合标准的沿革来源与统治者年表来源；
3. 扩写政权简介，保持事实密度与中性表述；
4. 录入人物、任期、角色、置信度和来源引用；
5. 聚合全部源分片并运行 JSON Schema 与语义校验；
6. 运行该批定向测试，抽查代表年份的统治者快照；
7. 检查生成详情包的人员与来源闭包；
8. 审查改动范围和文案质量，通过后进入下一批。

上一批的验证结果是下一批开始的基线。批次之间不需要额外人工确认，除非触发第 8 节的阻塞条件。

## 8. 异常与阻塞处理

以下情况需要暂停并请求决策：

- 权威来源之间的冲突会实质改变君主序列或政权边界；
- 现有数据模型无法准确表达所需史实；
- 必须修改共享 Schema、领域类型、生成器或页面组件；
- 某个目标政权无法找到达到既定标准的可靠来源。

普通年代分歧不构成阻塞。此时采用较主流或更权威来源的口径，并在 `chronologyNote`、`confidenceNote` 或任期说明中保留替代说法和不确定性。

单条来源失效时应寻找等质量替代来源，不能删除引用后继续录入，也不能通过放宽校验掩盖问题。

## 9. 测试策略

### 9.1 数据完整性

自动化测试需要证明：

- 55 个目标政权全部至少拥有一条统治记录；
- 每个目标政权的简介达到约定内容深度；
- 每个目标政权至少有一个有效来源引用；
- 人物、任期、空位和来源 ID 没有重复或悬空引用；
- 每段任期完全位于所属政权的一个存在区间内；
- 角色、年代精度、置信度和争议说明满足现有语义规则。

简介测试只设置防止遗漏和极短占位文本的合理下限，不把 100 至 200 字目标机械化为严格上限；内容质量仍需人工审查。

### 9.2 领域行为

从每个批次选取代表政权和年份，覆盖：

- 单一已知君主；
- 共治、摄政或主要争位；
- 年代或身份存在争议；
- 多段存在区间与复立边界；
- 资料尚未校订年份；
- 公元前后与闭区间端点。

### 9.3 生成与界面链路

生成器应继续为每个目标政权输出详情包，且包内只包含实际相关的人物、任期、空位和来源闭包。现有详情弹窗测试用于证明新增数据可以通过同一懒加载链路展示，不要求新增界面功能。

## 10. 验收标准

每批至少执行：

```bash
npm run validate:data
npm test -- tests/data-integrity.test.ts tests/ruler-snapshot.test.ts tests/data-artifacts.test.ts
```

全部五批完成后执行完整质量门禁：

```bash
npm run validate:data
npm test
npm run typecheck
npm run check:fonts
npm run build
git diff --check
```

最终验收结果为：

- 55 个非主线中国政权全部具备符合本设计的简介、统治者、任期和来源；
- 71 个中国政权均可在详情中提供已整理的统治者信息；
- 既有 16 个主线政权、时间轴、时间点浏览和详情懒加载不回归；
- 新增中文姓名和文案由站内字体子集完整覆盖；
- 结构化历史关系与事件仍明确处于本次范围之外。
