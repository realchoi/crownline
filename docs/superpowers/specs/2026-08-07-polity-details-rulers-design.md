# 阶段 3：政权详情与统治者设计

## 背景与目标

阶段 3 要把现有“条目说明”弹窗升级为可追溯的政权详情，并在时间点模式回答“这一年谁在位”。实现范围覆盖当前数据集中的 16 个中国主线政权；每个政权都录入其通行序列中的可考统治者，能够确定的任期尽量完整覆盖，早期或争议年代明确标成争议或资料不足，不为制造连续年表而虚构精确年份。

本阶段必须明确区分以下事实状态：有一位统治者、有多位同时在位或参与统治的人物、存在史学争议、已有来源支持的空位期，以及当前数据尚未校订。界面不得根据任期空档自动推断空位，也不得把资料缺失表述成“无人统治”。

## 方案选择

采用“显式状态模型 + 纯领域选择器 + 情境化详情弹窗”方案：

- `persons` 继续保存独立人物资料，`reigns` 继续保存人物在某一政权的统治、共治、摄政或争位任期。
- 数据契约升级到 v3，新增 `reignVacancies`，只保存有来源支持的明确空位期。
- 领域选择器根据政权、年份、任期与空位记录返回明确状态；没有命中任期或空位记录时返回“资料尚未校订”。
- 详情弹窗接收完整数据和可选的当前年份，在时间点模式展示当年统治者，在全览模式提示切换到时间点浏览，不读取用户当前不可见的默认年份。
- 详情中的政权、人物、任期和空位来源统一解析、去重并展示。

未采用以下方案：

1. 用名为“空位”的虚拟人物表达空位期。该方案会污染人物模型，使人物统计、搜索和后续关系建模产生错误语义。
2. 从任期空档自动推断空位。任期空档既可能是真实空位，也可能只是数据未收录，自动推断违反“不把资料缺失解释为历史事实”的原则。
3. 在弹窗内部直接筛选数组并拼装文案。该方案难以独立验证边界年份和多种状态，也会让阶段 4A 的共同年份统治者对比无法复用。

## 数据契约 v3

根对象的 `schemaVersion` 从 `2` 升级为 `3`，新增必填数组 `reignVacancies`。空数组仍是合法值，但本阶段会写入有可靠依据的空位记录。

任期增加可选 `localTitles`，用于保存与中文展示称号不同的本地文字称号：

```ts
interface Reign {
  id: string;
  personId: string;
  polityId: string;
  titles: string[];
  localTitles?: string[];
  role: "ruler" | "co-ruler" | "regent" | "contender";
  periods: HistoricalInterval[];
  chronologyStatus: "accepted" | "disputed";
  note?: string;
  sourceRefs: SourceRef[];
  confidence: ConfidenceLevel;
  confidenceNote?: string;
}
```

明确空位期使用独立记录：

```ts
interface ReignVacancy {
  id: string;
  polityId: string;
  periods: HistoricalInterval[];
  note: string;
  sourceRefs: SourceRef[];
  confidence: ConfidenceLevel;
  confidenceNote?: string;
}
```

每条任期和空位区间必须落在被引用政权的至少一个存在区间内。任期可以在同一年重叠，以表达共治、摄政和争位；空位区间不得与同一政权的任期重叠。`low` 或 `disputed` 记录继续强制填写 `confidenceNote`。

所有新人物、任期、空位和来源使用稳定 kebab-case ID。人物的 `names.primary` 保存页面常用名，`names.local` 保存可用的本地文字姓名，`names.aliases` 保存庙号、谥号、年号相关常用检索名；称号不塞入人物姓名。

## 当年统治者选择器

新增纯领域模块 `src/domain/rulerSnapshot.ts`，导出：

```ts
type RulerSnapshotStatus = "known" | "disputed" | "vacant" | "unrecorded";

interface RulerSnapshotEntry {
  person: Person;
  reign: Reign;
}

interface RulerSnapshot {
  polityId: string;
  year: number;
  status: RulerSnapshotStatus;
  entries: RulerSnapshotEntry[];
  vacancy?: ReignVacancy;
}

function selectRulerSnapshot(
  data: CrownlineData,
  polityId: string,
  year: number
): RulerSnapshot;
```

选择规则：

1. 使用项目统一的无公元 0 年、闭区间年份判定。
2. 收集该政权在指定年份命中的全部任期，并解析人物；按角色、任期起点和人物常用名稳定排序。
3. 命中任期中只要存在 `contender`、`chronologyStatus: "disputed"` 或 `confidence: "disputed"`，整体状态为 `disputed`。
4. 否则只要命中一条或多条任期，整体状态为 `known`；多条记录可能是共治或摄政，不自动视为争议。
5. 未命中任期但命中明确空位记录时，状态为 `vacant`。
6. 任期和空位都未命中时，状态为 `unrecorded`。

校验器保证人物引用和空位引用有效，因此选择器不吞掉悬空引用。若调用方传入不存在的政权 ID，选择器抛出带 ID 的错误，避免把编程错误伪装成资料缺失。

## 详情界面

详情弹窗延续现有史册式、纸张质感视觉语言，宽度适度增加并允许正文区域滚动。信息按阅读顺序组织：

1. 标题区：展示类别、名称、完整存在区间和关闭按钮。
2. 概述区：实体说明，以及年代采用口径、替代口径和可信度说明。
3. 元数据区：政权形态或实体类型、历史地区、所属历史阶段、累计持续时间。
4. 当年统治者区：仅时间点模式计算并展示快照。
5. 来源区：展示详情所引用的来源，并在当前年份存在统治者或空位记录时合并其人物与任期来源。

当年统治者区的状态文案与内容：

- `known`：标题为“某年 · 在位统治者”，展示一张或多张人物卡；角色徽章区分统治者、共治者和摄政者。
- `disputed`：标题保留年份，并以“存在争议”提示开头；展示所有命中人物和各自备注，不替用户裁定唯一结论。
- `vacant`：展示“已有资料记为空位期”和空位原因、采用区间及可信度说明。
- `unrecorded`：展示“这一年的统治者资料尚未校订”，明确不等于无人统治。

人物卡展示常用名、可选本地名、中文称号、可选本地称号、角色、完整任期、备注和争议说明。任期区间展示完整记录，而不是只显示命中的当前年份，以帮助理解共治与中断。

全览模式不展示隐藏的 `browseState.year`，而显示简短提示：“切换到时间点模式，可查看指定年份的在位统治者。”历史分期不是政权，其详情不显示统治者区域。

来源项优先显示 `citation`，同时展示可选的作者、出版者、定位信息和记录注释；有 URL 时使用新窗口链接并设置 `rel="noreferrer"`。同一来源被多处引用时只显示一次，但不同 `locator` 或 `note` 作为该来源下的补充定位合并展示。

## 数据覆盖与史料原则

当前 16 个中国主线政权全部进入统治者数据覆盖范围：夏、商、西周、东周、秦、西汉、东汉、西晋、东晋、隋、唐、北宋、南宋、元、明、清。

- 夏、商与西周早期不强求逐年精确，采用来源明确的通行序列，并以 `circa`、`unknown`、`chronologyStatus`、`confidence` 和说明披露不确定性。
- 秦及以后优先录入通行纪年可确定的统治者任期；同年交替按“该年任一时刻在位”规则允许多人同时命中。
- 武周期间不把唐的中断期算作唐朝任期；跨政权人物通过各自政权 ID 保存对应任期。
- 摄政者只在来源明确且对“当年谁实际参与统治”有解释价值时录入，不把所有太后、辅政大臣扩展为完整人物知识图谱。
- 非主线政权和四个外部样本本阶段不补齐；打开详情时明确显示资料尚未校订。
- 每条新增记录引用可核查来源；来源优先使用机构、学术出版物或可靠专题年表。无法可靠核定的精确年份留空档，不用单一百科条目填补争议。

“全部补全”表示 16 个主线政权均有经过校订的统治者数据，并覆盖通行序列中能够可靠落年的记录，不表示所有存在年份都能返回唯一人物，也不表示早期传世世系已经获得现代史学一致确认。

## 校验与错误处理

JSON Schema 继续负责字段形状、枚举、必填项和非零年份。语义校验新增：

- 空位记录引用的政权必须存在且必须是 `polity`。
- 任期引用的实体必须是 `polity`，不能引用历史分期。
- 任期与空位的每个区间必须完全包含在政权某个存在区间中。
- 同一空位记录的多个区间必须升序、互不重叠且不相邻。
- 同一政权的空位区间之间不得重叠，也不得与任期区间重叠。
- 任期的 `localTitles` 若存在，至少包含一个非空字符串。

数据加载失败继续使用现有全页错误边界；单条坏引用不会被 UI 静默忽略，而是在加载校验时阻止错误数据进入应用。

## 文件边界

- `src/domain/types.ts`：加入 `ReignVacancy`、`localTitles` 和 v3 根契约。
- `src/data/crownline-data.schema.json`：定义 v3 结构与空位记录。
- `src/domain/dataValidation.ts`：校验政权类型、任期/空位边界与冲突。
- `src/domain/rulerSnapshot.ts`：实现当年统治者纯选择器。
- `src/data/crownline-data.json`：补充 16 个中国主线政权的人物、任期、空位与来源。
- `src/components/DetailDialog.tsx`：展示完整政权详情、当年统治者状态和来源。
- `src/app/App.tsx`：向详情传入完整数据及时间点模式的当前年份。
- `src/styles/styles.css`：扩展详情排版、人物卡、状态提示、来源列表和窄屏样式。
- `tests/ruler-snapshot.test.ts`：覆盖领域状态与边界规则。
- `tests/data-validation.test.ts`、`tests/data-integrity.test.ts`：覆盖 v3 语义校验和主线数据完整性。
- `tests/app.test.tsx`：覆盖详情状态、来源和无障碍行为。
- `docs/data-contract.md`、`README.md`、`ROADMAP.md`：同步契约、功能、覆盖边界与阶段完成记录。

不新增运行时依赖，不引入路由或全局状态库，不修改浏览 URL 契约。

新增或修改的代码需要保留简洁的中文注释，重点解释历史年份闭区间语义、统治者状态判定优先级、资料缺失与明确空位的区别，以及跨记录校验中不直观的约束。显而易见的赋值、条件判断和 JSX 结构不逐行注释，避免注释遮蔽主流程。

## 测试与验收

TDD 顺序先完成领域选择器和校验，再接入 UI，最后补数据完整性测试。测试使用最小内存夹具验证规则，真实主数据只用于完整性和界面集成检查。

领域测试至少覆盖：

- 单一统治者命中。
- 同年共治者和摄政者同时命中但不误标争议。
- 争位者、争议年代或争议可信度触发 `disputed`。
- 明确空位返回 `vacant`，普通空档返回 `unrecorded`。
- 任期中断只在实际区间内命中。
- 区间起止年份均包含，跨公元前后跳过公元 0 年。
- 不存在的政权 ID 抛出清晰错误。

数据测试至少覆盖：

- 16 个主线政权均存在任期记录。
- 每条人物、任期、空位和来源引用有效。
- 任期和空位不越出政权存在区间。
- 数据中存在可供验收的单人、多人、争议、空位或无资料示例。

界面测试至少覆盖：

- 时间点详情显示当前年份与单人状态。
- 多人状态展示不同角色且保留所有人物。
- 争议状态披露说明，不只用颜色表达。
- 空位与无资料使用不同文案，且无资料明确“不等于无人统治”。
- 全览详情不误用隐藏年份，历史分期不显示统治者区域。
- 来源链接、关闭、Escape 和焦点恢复保持可访问。

最终执行：

```bash
npm run validate:data
npm test
npm run typecheck
npm run check:fonts
npm run build
```

并在桌面、窄屏、浅色和深色模式下检查弹窗的滚动、层级、对比度、长姓名及多人物布局。

## 非目标

- 不补齐 16 个主线政权之外的所有中国并行政权、区域政权或全球统治者。
- 不建设人物独立详情页、家族谱、继承关系图或完整帝王年表浏览器。
- 不允许用户在界面编辑史料或覆盖采用口径。
- 不在任期空档上自动推断空位、摄政或无政府状态。
- 不为阶段 4A 提前实现双政权对比，只提供可复用的领域选择器。
