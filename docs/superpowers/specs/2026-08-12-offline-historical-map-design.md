# Crownline 离线历史示意地图设计

**日期：** 2026-08-12
**状态：** 已确认，等待书面审阅
**对应路线图：** 阶段 5 · 时间轴 / 地图双模式（能力 6）

## 背景

Crownline 已完成时间点浏览、地区范围、多地区完整全览、政权详情与统治者、双政权时间对比及结构化历史关系。当前所有核心能力仍以时间线为主要空间，无法回答“这些政权在当时大致位于哪里”，也没有验证同一浏览状态在时间与空间两种视图间切换的能力。

阶段 5 首版采用离线 SVG 示意地图，不接入在线瓦片、后端或历史疆域多边形。地图只展示有来源、带适用时间和精度说明的都城、政治中心或代表性中心点，不把单点解释为完整疆域，也不从点位推导接壤、重叠或主权关系。

## 目标

1. 在当前年份和地区范围下，用世界示意地图展示已校订的政权地理点位。
2. 时间轴与地图共享年份、地区、搜索、类别、详情和双政权对比状态。
3. 地图点位具备时间有效期、位置精度、限制性说明、可信度与可追溯来源。
4. 点击地图标记或地图结果列表，可进入现有详情和对比流程。
5. 地图加载或单条地理记录异常时，不破坏时间轴及其他现有能力。
6. 手机、键盘和屏幕阅读器用户可通过与地图等价的结果列表完成核心浏览。

## 非目标

- 不绘制历史疆域多边形、现代国界或精确行政边界。
- 不从点位推断政权接壤、疆域重叠、控制范围或历史关系。
- 不接入在线瓦片、地图账户、地图 API 或后端服务。
- 不在首版提供自由缩放、拖拽漫游、完整事件地图或动画迁都轨迹。
- 不在首版补齐全部 91 个政权的地理点位。
- 不借地图阶段建设完整历史地理信息系统或事件知识图谱。

## 总体方案

应用继续使用 React、Vite、TypeScript 和静态 JSON 产物。世界陆地轮廓由本地 SVG 提供，点位通过等距圆柱投影转换为容器中的百分比坐标，并使用覆盖于 SVG 上的原生 HTML 按钮呈现。

地理快照从源数据独立生成 `public/data/generated/geography.json`，首次进入地图时按需加载。这样可隔离地图数据错误，避免增加时间轴首屏索引体积，并为后续可能增大的地理数据保留独立加载边界。

底图采用 Natural Earth 1:110m Land 的公共领域数据派生为简化 SVG。仓库保留底图来源、版本、许可说明和派生方式；页面固定显示来源与“示意而非精确勘界”的说明。生产运行不请求任何在线地图资源。

## 数据契约 v4

阶段 5A 将完整数据、首屏索引、实体详情与地理产物统一升级为 `schemaVersion: 4`。现有 v3 字段语义保持不变，只增加地理快照与独立地理运行时产物。

### 地理快照

```ts
export const GEOGRAPHIC_ROLES = [
  "capital",
  "political-center",
  "representative-center"
] as const;

export const POSITION_PRECISIONS = [
  "exact",
  "approximate",
  "regional"
] as const;

export interface GeographicCoordinates {
  latitude: number;
  longitude: number;
}

export interface GeographicSnapshot {
  id: string;
  polityId: string;
  periods: HistoricalInterval[];
  placeName: string;
  role: (typeof GEOGRAPHIC_ROLES)[number];
  coordinates: GeographicCoordinates;
  positionPrecision: (typeof POSITION_PRECISIONS)[number];
  positionNote: string;
  sourceRefs: SourceRef[];
  confidence: ConfidenceLevel;
  confidenceNote?: string;
}
```

字段含义如下：

- `periods` 表示该位置作为指定角色的适用时间，不表示政权在此之外不存在。
- `capital` 仅用于来源明确称为都城或首都的地点。
- `political-center` 用于有来源支持、但不宜直接套用“首都”概念的政治中心。
- `representative-center` 只用于帮助浏览定位，必须在 `positionNote` 中解释选择依据与限制。
- `coordinates` 使用 WGS 84 十进制度；其现代坐标只用于把历史地点投影到示意图。
- `positionPrecision` 描述坐标定位精度，不等同于历史叙述整体可信度。
- `positionNote` 为必填字段，必须说明古今地名映射、坐标口径或示意限制。
- `confidence` 与 `confidenceNote` 延续现有数据契约的可信度语义。

### 独立运行时产物

```ts
export interface CrownlineGeography {
  schemaVersion: 4;
  geographicSnapshots: GeographicSnapshot[];
  sources: Source[];
}
```

`geography.json` 只包含地理快照及其引用的来源闭包。地图加载器返回经过运行时收窄的有效快照，并同时返回被跳过的异常记录数量。

### 数据组织

- 人工维护源数据放在 `src/data/source/geography/geographic-snapshots.json`。
- `scripts/data-source.ts` 将地理快照聚合进完整 `CrownlineData`。
- `scripts/generate-data.ts` 在全量校验后生成独立 `geography.json`。
- `.generated/data/crownline-data.json` 继续包含完整数据，供测试和工具使用。
- `index.json` 不包含地理快照；时间轴首屏不会因地图数据增长而变大。

### 语义校验

完整数据生成必须拒绝以下情况：

- 快照 ID 与任一全局稳定 ID 重复。
- `polityId` 悬空或指向历史分期。
- 来源引用悬空。
- 纬度不在 `-90..90`，或经度不在 `-180..180`。
- 快照区间无效、包含公元 0 年、相邻或互相重叠却未合并。
- 快照任一适用年份不在关联政权的存在区间内。
- `positionNote` 为空。
- `confidence` 为 `disputed` 却缺少 `confidenceNote`。
- 同一政权、地点、角色和区间形成重复记录。

同一政权可在同一年拥有多个有效点位，以表达双都、巡回宫廷或多个政治中心；界面不得擅自选择唯一中心。

## 共享浏览状态

现有 `BrowseMode = "overview" | "point"` 继续只表达时间轴的完整全览与历史时间点。新增独立视图维度：

```ts
export type ViewMode = "timeline" | "map";

export interface BrowseState {
  viewMode: ViewMode;
  mode: BrowseMode;
  year: number;
  query: string;
  category: CategoryFilter;
  regionScope: RegionScope;
  compareEntityIds: string[];
}
```

URL 使用 `view=map` 表示地图视图；时间轴为默认值，不写入 `view`。现有 `mode`、`year`、`q`、`type`、`scope`、`region` 和重复 `compare` 参数继续沿用。

地图始终按 `year` 显示时间点结果，但不会改写 `mode`。因此用户从完整全览进入地图，再返回时间轴时，仍回到完整全览；从时间点进入地图则返回同一时间点模式。进入地图后年份控件始终可见。

无效 `view` 值清洗为 `timeline`。视图切换、刷新和分享链接不得丢失其他已知参数，也继续保留调用方不认识的查询参数。

## 数据流

```text
BrowseState（视图、年份、地区、搜索、类别、对比）
    │
    ├─ timeline ─► 现有 selectBrowseResults ─► Timeline / TimepointView
    │
    └─ map ─► 当年真实政权结果
                 + 按需加载 CrownlineGeography
                 └─► selectGeographicSnapshots
                         ├─► 地图标记与聚合
                         ├─► 可访问结果列表
                         └─► 缺少点位与异常记录摘要

地图标记或列表项
    ├─► 现有 DetailDialog
    └─► 现有 ComparisonPanel
```

`selectGeographicSnapshots` 只消费已完成地区、搜索、类别和年份筛选的真实政权，以及有效地理快照。它输出稳定排序的可见点位、聚合组、存在但缺少点位的政权，以及被运行时跳过的异常记录数量。

## 页面交互

筛选区增加一级视图切换“时间轴 / 地图”。

- 时间轴视图继续显示“完整全览 / 历史时间点”。
- 地图视图隐藏该二级切换，但显示年份输入、逐年步进和滑杆。
- 地区、搜索、类别和对比选择在两种视图间共享。
- 地图只显示当前年份存在的真实政权，不显示历史分期。
- 结果摘要同时说明可见政权数、地图点位数与缺少地理数据的政权数。

世界轮廓使用响应式 SVG。点位使用覆盖于 SVG 上的原生 HTML `button`，标记的无障碍名称包含政权、地点和角色，例如“北魏，洛阳，都城”。点位视觉样式区分都城、政治中心和代表性中心，但不使用颜色作为唯一辨识方式。

点击点位打开现有详情弹窗。地图结果列表为每个政权提供相同的详情入口和“加入对比”操作，继续遵守最多选择两个真实政权的规则。

投影后距离过近的点位组成确定性的聚合标记。聚合不随机移动点位；点击聚合标记后展开该聚合内的地点和政权列表。相同输入在刷新、筛选或测试中必须得到相同分组和顺序。

地图下方始终显示与当前地图同步的结果列表。列表不是降级提示，而是核心等价入口：用户可以不操作地图完成详情浏览和双政权对比。

## 组件与领域边界

- `ViewModeControl`：呈现并切换时间轴/地图，不持有业务状态。
- `HistoricalMap`：呈现本地底图、点位与聚合，发出选择事件。
- `MapResultList`：呈现与地图一致的可访问结果、详情与对比入口。
- `MapLoadPanel`：呈现地理数据加载、失败、重试与不可用状态。
- `mapSnapshots.ts`：负责年份匹配、快照选择、投影、聚合和稳定排序。
- `loadCrownlineGeography.ts`：负责按需请求与地理运行时数据收窄。
- `App.tsx`：继续统一持有共享浏览状态、详情选择和对比选择。

地图相关领域逻辑不得写进 React 组件。`App.tsx` 只增加视图组合与地理加载状态，不借本阶段重构现有时间轴、详情或比较模块。

## 加载与异常处理

- 第一次进入地图时请求本地 `geography.json`，成功结果在当前页面生命周期内缓存。
- 加载中显示状态提示，同时保留切回时间轴的能力。
- 加载失败显示错误原因和重试按钮；时间轴、详情和对比保持可用。
- 重试或快速切换视图时使用请求序列隔离迟到结果，旧请求不得覆盖新状态。
- 根对象或必需数组无效时，整个地图数据标记为不可用。
- 单条地理快照无效时只跳过该记录，并在地图结果摘要中显示跳过数量。
- 当年没有匹配政权时，沿用现有地区覆盖与筛选空状态口径。
- 当年存在匹配政权但没有有效点位时，显示“这些政权尚未校订地理数据”，不表述为历史上不存在。
- 部分政权有点位、部分缺失时，地图正常显示有效点位，并在结果列表中单独列出缺失项。

## 无障碍与响应式要求

- 视图切换使用原生按钮和 `aria-pressed`，不模拟不完整的选项卡语义。
- 每个标记可通过 Tab 聚焦，并具备可见焦点样式。
- 聚合按钮公布包含的点位数量；展开后焦点进入聚合结果，关闭后返回触发按钮。
- 地图的动态加载、异常跳过和结果数量通过状态区域播报，避免重复播报每次滑杆输入。
- 结果列表与地图使用同一领域选择结果，防止两套入口内容不一致。
- 375px 宽度下地图不产生页面横向滚动，结果列表保持完整可操作。
- 深色和浅色模式下陆地、海洋、标记、聚合、焦点和文本均保持可辨识。
- `prefers-reduced-motion` 下禁用非必要的标记或聚合过渡。

## 测试策略

### 数据契约与完整性

- JSON Schema 覆盖新增类型、必填字段、枚举和坐标结构。
- 语义测试覆盖坐标边界、公元 0 年、无效区间、悬空政权、悬空来源、超出政权存在期、重复快照和争议说明缺失。

- 生成产物测试确认 `index.json` 不携带地理快照，`geography.json` 只携带地理来源闭包。

### 领域逻辑

- 测试区间端点、多段存在期、多个同时有效中心和无公元 0 年口径。

- 测试等距圆柱投影的边界坐标和百分比结果。
- 测试聚合阈值、稳定排序和相同输入的确定性。
- 测试存在但缺少点位的政权不会被误报为不存在。

### URL 与组件

- 测试 `view=map` 恢复、非法值清洗、未知参数保留及视图往返。
- 测试从完整全览或历史时间点进入地图，再返回时恢复原模式。
- 测试地图加载、失败、重试、迟到请求、空结果和单条坏记录跳过。
- 测试地图标记和结果列表都能打开详情并操作双政权对比。
- 测试键盘名称、聚合展开、焦点恢复和状态提示。
- 回归现有时间轴、时间点、详情、对比和历史关系测试。

## 分阶段实施

### 阶段 5A：数据契约与首批点位

升级契约 v4，增加地理源数据聚合、严格校验、独立生成产物和 35 个首批政权的地理快照。该阶段完成后，即使尚无地图界面，地理数据也必须能够独立生成、验证和测试。

## 验收标准

阶段 5 只有同时满足以下条件才可标记完成：

1. 20 个世界样本与 15 个中国代表政权均至少有一条可追溯地理快照。
2. 北魏、明、清能按年份显示不同的有效政治中心。
3. 时间轴与地图共享年份、地区、搜索、类别、详情和双政权对比状态。
4. 视图切换、刷新和分享链接后状态正确恢复。
5. 地图标记和等价结果列表均可进入详情与对比。
6. 无地图数据、部分缺失、加载失败和单条坏记录均有准确且不误导的界面反馈。
7. 地图不绘制或推断历史疆域、接壤、空间重叠与主权关系。
8. 核心地图浏览可由键盘完成，手机用户无需精确点击地图标记。
9. 生产运行不依赖在线地图服务，GitHub Pages 静态部署继续可用。
10. 数据校验、自动化测试、类型检查、字体覆盖检查和生产构建全部通过。
