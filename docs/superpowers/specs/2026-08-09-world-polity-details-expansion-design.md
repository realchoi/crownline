# 世界政权详情补全设计

## 1. 背景与目标

Crownline 当前已完整整理数据集内 71 个中国政权的详情与统治者，但其他地区仍只有拜占庭帝国、阿拔斯哈里发、神圣罗马帝国和朱罗帝国四个机制验证样本。这四个条目只有简短简介和基础来源，人物、任期与特殊统治角色仍为空，时间点详情只能显示“资料尚未校订”。

本次先不扩大世界政权数量，而是把这四个现有样本补齐为可用于正式浏览的详细条目。每个政权需要具备深入简介、完整正式统治者序列、来源支持的重要共治者、摄政者和主要争位者，以及可追溯的年代与来源说明。完成后，其他地区与中国政权应通过同一详情加载与统治者快照链路呈现。

## 2. 范围与非目标

本次范围包括：

- 扩写四个政权的简介、名称与年代说明；
- 录入人物、统治任期、角色、称号、年代精度、置信度与来源；
- 只在史料明确支持时录入统治空位；
- 更新地区覆盖说明、数据完整性测试和代表年份测试；
- 同步 README、ROADMAP 与数据契约中的覆盖统计及说明。

本次不新增历史政权，不建立战争、外交等结构化关系，不补事件或地图数据，不修改页面功能、JSON Schema、TypeScript 领域类型、生成器或运行时详情包格式。若可靠表达史实必须突破这些边界，应暂停并请求决策，不在本次任务中隐式扩张。

## 3. 方案选择

采用“逐政权纵向补全”方案，依次处理拜占庭帝国、阿拔斯哈里发、神圣罗马帝国和朱罗帝国。每个政权都要完成简介、人物、任期、来源和定向验证的完整闭环，再进入下一个政权；四个政权完成后统一运行完整质量门禁。

该方案比一次性录入四个政权更容易定位人物 ID、任期边界和来源引用错误，也比按地区分批更能隔离不同史学传统下的称谓与继承问题。批次之间不需要额外人工确认，除非触发第 8 节的阻塞条件。

## 4. 数据架构与文件边界

沿用现有 schema v3。四个政权继续分别维护在 `src/data/source/entities/world/` 下的实体分片中：

- `description`：约 100 至 200 字，覆盖形成背景、统治中心或主要范围、关键演变和终结方式；
- `persons`：保存人物主名称、本地名称与常见别名，同一人物只建立一条记录；
- `reigns`：记录正式统治者及重要共治者、摄政者和主要争位者的角色、称号、一个或多个任期区间与来源；
- `reignVacancies`：只记录有明确来源支持的统治空位，不能从任期资料缺口推断；
- `chronologyNote`、`alternativeChronologies`、`confidence` 与 `confidenceNote`：表达边界、称谓和序列争议；
- `sourceRefs`：为政权沿革、年代和统治任期提供可追溯引用。

公共数据改动限于：

- `src/data/source/sources/sources.json`：增加权威机构、学术著作和可靠年表来源；
- `src/data/source/regions/regions.json`：更新欧洲、西亚、南亚和北非的覆盖说明，但仍保持谨慎的覆盖等级；
- `tests/`：加入四个政权的数据完整性、代表年份和生成详情包测试；
- `README.md`、`ROADMAP.md`、`docs/data-contract.md`：同步当前数据规模与覆盖说明。

现有生成器继续负责聚合分片、执行 JSON Schema 与语义校验，并生成按实体懒加载的详情包。页面组件不因本次数据补全而修改。

## 5. 史料与统治者口径

### 5.1 来源标准

来源按以下顺序选择：

1. 博物馆、大学、政府文化机构和权威百科；
2. 学术出版社的历史著作、研究工具或可核查年表；
3. 可靠工具书，用于交叉核对人物称谓和统治序列；
4. Wikipedia 等三级来源只辅助核对姓名、别名和序列，不单独支撑争议结论。

每个政权至少需要一项直接支持其沿革和年代的来源。每条人物任期必须绑定来源；同一权威年表可以复用，但每条业务记录仍保留明确的 `sourceRefs`。来源之间存在一般年代差异时，采用较权威或较主流口径，并在年代、置信度或任期说明中保留替代说法。

### 5.2 名称、角色与任期

- 中文常用名作为人物主名称；原文名称、本名、帝号和其他常见译名按现有名称结构保存；
- 正式统治者完整收录，重要共治者、摄政者和主要争位者使用结构化角色，不只写进简介；
- 同一人物复位或任期中断时，使用一条任期记录中的多个区间；
- 任期采用闭区间语义，同年交替允许多位统治者同时命中，因为时间点查询表示“该年任一时刻在位”；
- 任期必须完整落在所属政权的一个存在区间内，不得跨越政权中断；
- 无法确认到精确年份时使用 `circa` 或 `unknown`，不得制造虚假精度；
- 没有任期也没有明确空位的年份继续表示“资料尚未校订”。

## 6. 政权收录边界

### 6.1 拜占庭帝国

沿用约 330—1453 年的展示区间，收录该口径下的皇帝序列，并处理重要共治皇帝、摄政、废黜与复位。第四次十字军后，1204—1261 年占据君士坦丁堡的拉丁帝国不并入拜占庭统治者序列；拜占庭帝国按尼西亚帝国的继承口径延续，并在年代说明中明确该选择。

### 6.2 阿拔斯哈里发

沿用 750—1258 年巴格达时期口径，收录该阶段的阿拔斯哈里发。1261 年后的开罗象征性哈里发世系不并入当前政权。布韦希、塞尔柱等实际掌权者不作为阿拔斯正式统治者录入；其对哈里发权力的影响只在有助于解释政权演变时写入简介或任期注释。

### 6.3 神圣罗马帝国

沿用 962—1806 年展示区间，并保留从 800 年追溯帝国传统的替代口径。正式统治序列以罗马人的国王和皇帝为主；当选但未获皇帝加冕的统治者仍可作为正式统治者，称号按具体时期记录。对立国王只在具有显著政治影响且来源明确时作为主要争位者收录。

### 6.4 朱罗帝国

沿用约 850—1279 年的中世纪帝国阶段，不把更早的传说或前中世纪朱罗传统并入。共治王储只在来源能够支持实际共同统治时录入；晚期统治序列若存在实质年代分歧，应降低置信度并解释采用口径。

## 7. 数据流与分批执行

每个政权按照同一顺序处理：

1. 核对现有名称、存在区间、年代说明与地区归属；
2. 检索并筛选符合标准的沿革来源与统治者年表来源；
3. 扩写政权简介，保持中性表述和足够事实密度；
4. 录入人物、任期、角色、称号、精度、置信度与来源引用；
5. 聚合全部源分片并运行 JSON Schema 与语义校验；
6. 运行该政权的定向完整性和代表年份测试；
7. 检查生成详情包的人物、任期与来源闭包；
8. 通过后进入下一个政权。

全部四个政权完成后，统一更新地区覆盖说明和项目文档，再运行完整回归验证。

## 8. 异常与阻塞处理

以下情况需要暂停并请求决策：

- 权威来源冲突会实质改变统治者身份、统治序列或政权存在边界；
- 现有角色、区间或置信度模型无法准确表达需要收录的史实；
- 必须修改共享 Schema、领域类型、生成器、页面组件或其他超出范围的公共契约；
- 某个政权无法找到达到既定标准的可靠沿革或统治者来源。

一般年代分歧不构成阻塞。此时采用较权威或较主流口径，并在 `chronologyNote`、`confidenceNote` 或任期说明中披露替代说法。单条来源失效时应寻找同等质量的替代来源，不能删除引用后继续录入，也不能放宽校验掩盖问题。

## 9. 测试与验证策略

### 9.1 数据完整性

自动化测试需要证明：

- 四个目标政权的简介达到约定内容深度并至少引用一项有效来源；
- 每个政权至少拥有一条正式统治任期，并通过按政权维护的预期人物 ID 或数量断言防止整批遗漏；
- 人物、任期、空位和来源 ID 没有重复或悬空引用；
- 每段任期完整位于所属政权的一个存在区间内；
- `low`、`disputed` 和其他需要说明的记录均包含必要注释；
- 地区覆盖说明与实际收录状态一致。

自动化测试只能防止结构性遗漏，不能证明历史序列本身完整。每个政权进入下一批前，还需要把正式统治者序列与所采用的权威年表逐项对照；一般年代差异必须有说明，无法解释的人物缺失视为未完成。

### 9.2 领域行为

每个政权选择代表年份，覆盖适用的以下状态：

- 单一已知统治者；
- 共治、摄政或主要争位；
- 废黜、复位或不连续任期；
- 年代或身份争议；
- 闭区间端点与同年交替；
- 资料尚未校订。

### 9.3 生成与界面链路

生成器应继续为四个目标政权输出详情包，且包内只包含相关人物、任期、空位和来源闭包。现有详情弹窗和统治者快照测试用于证明新增数据可以通过同一懒加载链路呈现，不新增页面交互。

每个政权至少执行：

```bash
npm run validate:data
npm test -- tests/data-integrity.test.ts tests/ruler-snapshot.test.ts tests/data-artifacts.test.ts
```

全部完成后执行：

```bash
npm run validate:data
npm test
npm run typecheck
npm run check:fonts
npm run build
git diff --check
```

## 10. 验收标准

最终交付需要满足：

- 拜占庭帝国、阿拔斯哈里发、神圣罗马帝国和朱罗帝国均具备详细简介、完整正式统治者序列及有来源支持的重要特殊角色；
- 四个政权在时间点详情中能够返回符合当年情况的统治者状态，不再整体显示为未校订；
- 现有年代边界和史学争议没有被静默改写；
- 欧洲、西亚、南亚和北非的覆盖说明准确反映本次深化，但不声称已经形成完整地区通史；
- 中国 71 个政权、时间轴、地区筛选和详情懒加载没有回归；
- 新增中文名称与文案由站内字体子集完整覆盖；
- 历史关系、事件、地图、Schema 和页面交互仍明确处于本次范围之外。
